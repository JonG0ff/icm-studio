# Business Memory

Approved business, brand, offer, and project context for your work.

Read selected entries to fill missing company, brand, SOP, offer, CTA, and approved project details. Reading existing records does not require a maintenance workflow. Use stages to propose, approve, or validate records. Do not treat it as conversation memory.

## Task Routing

| Task Type | Go To | Description |
|-----------|-------|-------------|
| Add or configure a brand | `stages/01-brand-setup/CONTEXT.md` | Create or update a brand folder under `brand-vault/brands/` |
| Read approved brand context | `brand-vault/CONTEXT.md` | Route to identity, voice, tokens, or themes |
| Find a content SOP | `sops/CONTEXT.md` | Choose the smallest SOP for the content job |
| Find a content type template | `content-types/CONTEXT.md` | Load format constants and required sections |
| Find an offer, affiliate link, or partner rule | `offers/CONTEXT.md` | Load offer terms, compliance, and placements |
| Propose or approve project memory | `stages/02-project-memory/CONTEXT.md` | Save approved project facts and decisions |
| Validate Business Memory links | `stages/03-validation/CONTEXT.md` | Find stale local brand files or broken pointers |

## Shared Resources

| Resource | Location | Contains |
|----------|----------|----------|
| Brand vault | `brand-vault/CONTEXT.md` | Brand routing, identity, voice, tokens, themes |
| SOP library | `sops/CONTEXT.md` | Content production procedures |
| Content templates | `content-types/CONTEXT.md` | Format constants and reusable sections |
| Offer records | `offers/CONTEXT.md` | Affiliate links, partner terms, compliance, placements |
| Project memory | `project-memory/CONTEXT.md` | Approved project facts and decisions |

## Rules

- Load one brand at a time.
- Approved project memory is the only project memory future work should rely on.
- Draft notes, brainstorms, and route bundles are not memory until approved.
- Keep entries small and pointer-like.
- Do not move `../swipes/knowledge-layer/` here.
- Return approved record pointers to the requesting job artifact. No separate run card is required.
