# Context Pointer Rules

A brief records selected context and its purpose. Canonical facts, reference analysis, and reusable media records keep their library homes.

Paths below are relative to this template folder. In completed briefs, write repository-relative paths or clearly name another base.

## Business Context

- Approved brands: `../../../libraries/business-memory/brand-vault/brands/`.
- Approved project facts: `../../../libraries/business-memory/project-memory/`.
- Business-specific SOPs and content standards: `../../../libraries/business-memory/sops/` and `../../../libraries/business-memory/content-types/`.
- Load one relevant brand and selected sections. Mark missing facts unknown; do not invent them.

## Reference Context

Search `../../../libraries/swipes/knowledge-layer/index.md`.

- Record entry path, selected sections, and why they matter.
- If missing, record the source URL/file and route reference maintenance to `../../../libraries/swipes/CONTEXT.md`.
- A reference can guide technique without being cleared for publication. Do not copy swiped text or turn reference media into approved production assets.

## Media Context

Check `../../../libraries/media/assets/index.md` before sourcing.

- Record asset ID, record path, intended use, local path, and rights/status.
- Let the production workspace source job-specific gaps using the relevant skill/tools and record selections in its manifest.
- Promote reusable finds only through `../../../libraries/media/CONTEXT.md` and its approval workflow.
- Preserve unknown, unclear, pending, needs-approval, and internal-reference-only states honestly. A downloaded file is not clearance.
